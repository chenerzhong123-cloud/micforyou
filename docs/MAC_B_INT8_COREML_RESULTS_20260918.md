# Mac B INT8 + CoreML returned results — 2026-09-18

Scope: audit of the sanitized return bundle `mac-b-runtime-return-20260918-214338`. The bundle manifest matched every returned file's SHA-256 and byte count. It contained no audio, checkpoint, enrollment, transcription or ONNX artifact.

## Accepted evidence

### Dynamic INT8 — correctness FAIL

Default ONNX Runtime dynamic quantization reduced the reported model size from 85,313,823 to 23,329,226 bytes. The graph contained 12 `DynamicQuantizeLSTM` and 174 `DynamicQuantizeLinear` nodes after conversion.

The corrected 100-chunk comparison used the real checkpoint and locally precomputed enrollment conditioning. It stayed finite but diverged catastrophically from FP32:

| Metric | Result |
| --- | ---: |
| First-chunk output max absolute error | 0.9647 |
| 100-chunk output max absolute error | 1.4053 |
| Output relative L2 error | 1.2508 |
| Largest final c-state error | 151.79 |

This validly fails the INT8 correctness gate. The INT8 performance matrix was correctly left `NOT_RUN`; speed cannot rescue a numerically different recurrent model.

### CoreML graph correctness and partition — PASS as diagnostics

Static 8/16/24-frame ONNX graphs passed the returned 100-chunk correctness checks with max absolute errors between 2.56e-06 and 3.10e-06.

CoreML EP reported 18 supported partitions and 2,071 of 2,248 graph nodes supported. The detailed capability log also reports all 12 `LSTM` nodes as unsupported (`supported: [0]`), so the recurrent path fell back to CPUExecutionProvider. This placement evidence is accepted.

## Rejected performance conclusion

The returned report declared CoreML FAIL with best RTF 1.459 and therefore `WINNER=NONE`. Code review found that conclusion is premature:

```python
session = build_session("coreml", 1, ...)
thread_values = [0]
label = "auto"
```

The CoreML session explicitly set `intra_op_num_threads=1`, while the JSON labeled it `auto`. Because every LSTM runs on CPU fallback, this is a material benchmark variable. The prior ORT CPU 24-frame matrix measured RTF 3.484 with one thread versus 1.551 with four threads. The returned CoreML RTF values are therefore valid only as an explicitly one-thread probe, not as the requested auto/4-thread CoreML matrix.

Returned one-thread CoreML observations, relabeled correctly:

| Static frames | RTF | p95 | Status |
| ---: | ---: | ---: | --- |
| 8 | 2.759 | 212 ms | diagnostic only |
| 16 | 1.832 | 249 ms | diagnostic only |
| 24 | 1.459 | 293 ms | diagnostic only |

The project must not claim `CURRENT REAL-TSE ON M1: STOP` until the corrected CoreML auto/4-thread fallback matrix is run. INT8 remains failed; only the CoreML performance gate is reopened.

## Environment metadata discrepancy

The result narrative says Python 3.12.14, while `ENVIRONMENT.txt` says Python 3.9.6. The earlier raw ORT CPU JSON records Python 3.12.14. The most likely explanation is that the environment file was generated by the system interpreter rather than the experiment venv, but this is not proven. The corrected rerun must record `sys.executable` and `platform.python_version()` from the exact benchmark process.

## Integrated code changes

The five returned experiment scripts were reviewed and imported. Before integration, the following corrections were made:

- CoreML now builds a distinct session for every requested ORT thread setting and reports the exact setting actually applied.
- `auto` leaves ORT thread counts unset; explicit values are no longer mislabeled.
- session logs are separated by thread setting and file descriptors are closed.
- report paths are sanitized to filenames/placeholders rather than private absolute paths.
- INT8 correctness derives recurrent dimensions from the model and checks non-finite state values as well as outputs.
- quantization reports now compute the full before/after operator delta, including `MatMulInteger`/`ConvInteger`, instead of filtering only names containing `Quant`.
- ONNX/ORT experiment dependencies are pinned in `requirements-real-tse.txt`.
- pure unit tests lock the auto/4-thread setting contract.
