# 暂停过滤时原音直通：软件更新 plan

日期：2026-10-08。状态：方案已实施，自动检查与真实 ONNX 合成输入验证已完成；**真实设备 / 豆包 / 新版 30 分钟验收仍待完成**。当前结果见 [验证记录](PAUSE_PASSTHROUGH_VALIDATION.md)。下文保留实施契约与完整验收矩阵，未将未执行项标为通过。

## 目标与推荐实现

「暂停」只暂停过滤，把当前所选实体麦克风的原始声音继续送给输入法；「继续过滤」恢复本人声音提取；「结束」才停止声音输出并释放麦克风。

推荐保留同一个音频进程、同一个输入输出 Stream，在音频块边界切换 TSE 与原音直通。这样输入法不需要重新选设备，也避免每次暂停、继续都关麦、重新打开音频路由。

暂停期间麦克风仍被占用，macOS 的麦克风使用指示仍会显示。原音直通包含本人、旁人和环境声音；界面需要持续明确显示这一状态。

宣传视频隐藏 BlackHole 模块与名称；实际音频路由继续使用它。README、首次设置与故障排查保留「安装 BlackHole 2ch，并将输入法输入设备设为 BlackHole 2ch」说明。此次不做替换驱动、改变系统默认输入、自动切换输入法设备或新增 ASR。

## 已核实的现状

| 现有实现 | 与新行为的关系 |
| --- | --- |
| `src/micforyou/cli.py` 的 `command_pause` 调用 `stop_managed_process(final_status="PAUSED")` | 当前暂停实际会结束音频进程，不能继续输出原声 |
| `src/micforyou/control.py` 停止进程组后清空 PID，记录「microphone released」 | 新的暂停必须保留进程归属、PID、健康监测；结束仍沿用安全停止机制 |
| `command_resume` 调用 `start_background` | 当前继续是重新启动进程；新继续应向现有进程发切换命令 |
| `ACTIVE_STATES` 不含 `PAUSED`；Swift `RuntimeStatus.isActive` 也不含它 | 新暂停仍在收音，必须更新活动状态判断，否则会误允许换设备、重新注册或重复启动 |
| `BridgeEngine` 有 TSE worker、有界输入队列与输出 ring | 切换时需要丢弃旧模式积压音频，防止旧输出迟到或跨状态泄漏 |
| `experiments/run_real_tse_bridge.py` 已有故障后原音透传逻辑 | 它是故障降级、重新打开 Stream 的路径，不能直接当作用户暂停实现；可复用声道映射函数 |
| `MenuContentView.swift` 显示「实体麦克风已释放」「BlackHole 当前无输出」 | 必须改为「过滤已暂停」「原始声音继续输入」，保持可见的原音状态 |
| `tests/test_control.py` 现有暂停测试断言 PID 清空 | 这是旧行为契约，需要替换为「暂停保留进程，结束释放进程」 |
| 工作区另有 C01 App 图标与菜单头部品牌接入改动 | 保留该工作，不重复替换资源；此次计划聚焦暂停行为，并核对视频、App 使用同源 Logo |

依据为当前仓库代码。当前 M5 的过滤运行验证和 M1 不支持结论保持原有范围；本计划不宣称新的硬件兼容性或更强过滤效果。

## 状态与输出契约

对 CLI 和界面保留 `pause`、`resume` 及 `PAUSED` 名称，但更改其行为。进程生命周期与声音处理模式分别记录，不再以「PAUSED」推断麦克风已释放。

建议新增运行元数据字段：`processing_mode`（`tse` / `passthrough` / `none`）、`mode_reason`（例如 `user_pause` / `fault_fallback`）、`requested_mode`、`mode_revision`。字段名在实施时统一定稿；不得记录音频、声纹、转写内容。

| 用户操作 / 状态 | 进程与设备 | 送往输入法的声音 | 持续显示 |
| --- | --- | --- | --- |
| 尚未开始 / 已结束 | 不占用麦克风 | 无输出 | 可以开始 |
| 开始过滤 | 同一进程打开所选输入、现有输出；等待模型与路由准备好 | 准备阶段静音，不自动直通 | 正在加载 |
| 正在过滤 `RUNNING` | 音频 Stream 保持打开 | TSE 处理后的音频 | 正在过滤 |
| 暂停过滤 `PAUSED` | 同一 PID、同一 Stream 保持；停止提交 TSE 推理 | 原音直通，旁人声也会被送出 | 过滤已暂停 · 原始声音继续输入 |
| 继续过滤 | 原音继续到 TSE 新状态准备完成，再在块边界提交切换 | 成功后输出过滤音频；失败则保留已明确启用的原音模式，并显示恢复失败 | 正在恢复过滤，随后显示实际结果 |
| 结束 | 从过滤或暂停都能安全停止，关闭设备 | 无输出 | 可以开始 |
| 已提交的过滤路径发生运行故障 | 按现有默认故障策略恢复或终止 | 默认静音，不能把故障当成用户暂停而自动放行原声 | 正在恢复 / 已安全静音 |
| 所选输入断开、路由不可验证或输出失败 | 中断输出，仅等待或重开明确选定的设备 | 静音，不切到其他实体麦克风 | 设备异常 / 恢复中 |

旧版持久化的 `PAUSED`、`pid=null` 记录仍代表已停止收音。升级读取时必须识别为旧暂停记录，显示需要重新开启；不能伪报原音正在输出，也不能升级后自动启动收音。

## 实施步骤与交付

| 步骤 | 改动 | 主要文件 | 完成条件 |
| --- | --- | --- | --- |
| 1．定义状态与迁移 | 扩展运行状态和健康报告；定义实际模式、切换原因、版本与旧记录兼容；区分主动原音与故障降级 | `control.py`、`product.py`、`Models.swift` | 新旧状态可读取；暂停是否占麦不再靠字符串猜测；旧暂停不会自动收音 |
| 2．增加进程内控制通道 | 用本机 Unix domain socket 提交 `pause` / `resume`，带请求 ID、进程标识及确认结果；限制为当前用户可访问；命令有超时与幂等处理 | `control.py`、`cli.py`、音频运行脚本；可新增 `runtime_control.py` | 命令得到音频路径的确认后才回报成功；超时、重复命令和进程重启不会写出虚假状态 |
| 3．实现两种音频模式 | 在现有 Stream 的块边界切换；原音支路使用当前麦克风采样直接做必要声道映射，不经过模型或额外增益处理 | `bridging.py`、`experiments/run_real_tse_bridge.py` | 暂停仍有输出；原音不被 TSE、重采样链或额外增益改变；暂停阶段模型调用不再增长（允许切换前已在执行的一次调用完成） |
| 4．处理切换与缓冲 | 切换时清除旧输入队列、输出 ring，更新 generation；晚到的旧 worker 输出被丢弃；继续时重新建立 resampler、STFT/OLA 和 recurrent state | 同上及 `runtime.py` 的流式状态适配 | 无旧句重放、叠音、跨模式尾音；回调不承担模型加载、阻塞控制或文件 IO |
| 5．接入 CLI 与生命周期 | `pause` 不再调用终止进程；`resume` 切换现有进程；`stop` 仍关闭进程；重复启动被拒绝；仅完全结束后可换设备、重新注册或修改策略 | `cli.py`、`control.py`、`product.py` | 新暂停仍受进程归属和存活检查管理；设备变更和 enrollment 不会与原音收音竞争 |
| 6．更新 GUI | 用「暂停过滤」「继续过滤」「结束」区分三种行为；显示原音直通提示；旧 PAUSED 健康状态优先级不遮盖故障；设置项的可操作性按设备占用判断 | `MenuContentView.swift`、`Models.swift`、`AppModel.swift`、`SettingsView.swift`、`CLIClient.swift` | 点击结果与真实音频模式一致；故障有优先级；控制未确认时不提前显示成功 |
| 7．文档与品牌一致性 | 更新使用说明、隐私边界、状态表、旧版迁移；技术设置保留 BlackHole；宣传层隐藏模块；保留工作区已接入的 C01 App 品牌资源，核对与视频同源 | `README.md`、`SPEC.md`、`DESIGN.md`、`docs/STAGE_D.md`、`docs/APP_EXPERIENCE.md`、`docs/MENU_BAR_APP.md`、App 打包资源 | 所有「暂停＝释放麦克风／无输出」说明更新；结束与暂停不混淆；品牌图标来源可追溯 |
| 8．回归与真机验收 | 先完成离线行为测试，再做 Mac 音频及输入法端到端验收；记录模式切换与资源指标；最后更新对外视频的功能状态标注 | `tests/`、Swift model check、既有运行验收文档 | 下述验收矩阵通过后，才将暂停直通标为已实现 |

实施按 1 → 2–5 → 6–7 → 8 推进。推荐保留已加载模型与参考特征，暂停时降低推理负载，继续时重建流式状态；暂不新增用户设置或额外暂停模式。

### 两个实现细节需特别处理

1. **输出缓冲与时间位置。** 过滤链路有延迟、原音路径延迟更低。模式切换不能让两个路径同时写输出 ring。建议以 generation 隔离写入，在块边界选定唯一输出路径；只做消除切换爆音所需的短输出衔接，不增加持续性的原音处理。记录最大断点、丢弃块数和延迟变化，按下面的建议门槛验收。
2. **故障与用户意图。** 主动暂停产生的 `passthrough` 不标为 `DEGRADED`，但必须显示原音提示；原有故障后的 passthrough 若继续保留，仍标为故障降级，并遵循其显式策略。不要将默认 `fault_policy=silence` 改为 passthrough 来实现暂停。恢复过滤若准备失败且尚未提交 TSE 模式，保持用户之前主动启用的原音状态并明确提示；提交之后的运行故障仍按默认静音处理。

## 验收矩阵

以下为**待执行**验收，不是已通过的测试结果。数字为建议发布门槛，须在真机记录中报告实际值；现有标准更严格时取更严格值。

| 验收项 | 验证方法与通过条件 |
| --- | --- |
| 原音保真 | 将确定性 mono float32 块送入暂停支路；两个输出通道与输入按必要映射逐样本相等，无额外增益、裁剪、重采样或模型调用 |
| 过滤链路保持 | 原有 stateful correctness 与质量回归不退化；不能为了暂停改动提取模型、checkpoint 或 enrollment 规则 |
| 暂停保留设备 | 控制测试断言同一 PID 与 Stream 仍活跃，输入和输出继续；暂停不是 SIGINT/SIGTERM |
| TSE 调用暂停 | 完成切换前在途调用后，原音模式内模型调用计数不再增长；CPU 负载与过滤模式分别报告 |
| 继续与缓冲 | 用不同 generation 的带标记块验证：旧输出不得在新状态播放；清空并重建流式状态；原声与过滤声不得叠加 |
| 反复与并发操作 | 连续 100 次 pause/resume，另覆盖重复 pause、重复 resume、快速 pause→resume→stop、两个控制请求并发；无多个进程、重复 Stream、死锁或错误模式确认 |
| 结束与退出 | 从过滤、暂停、切换中都能结束；设备释放、PID 清除、无残留录音进程；保留现有「退出界面」行为，不把它偷偷改为结束音频 |
| 配置操作 | 运行与原音暂停时，换麦、enroll、set-policy 被阻止；只有结束后允许。旧版 PAUSED/pid=null 可安全开始，不自动收音 |
| 错误路径 | 模型异常、回调停顿、队列溢出、控制命令超时、进程意外退出都产生可验证的实际状态；不因错误暗中进入主动原音模式 |
| 设备故障 | 过滤与原音模式分别拔出实体麦克风；都不得自动转用内建麦克风；只重连原设备，输出在不可验证阶段静音 |
| Swift 状态 | 扩展 `Checks/ModelCheck.swift` 覆盖 PAUSED 的活动性、原音模式、故障覆盖、切换中、旧版记录；以真实 CLI JSON 验证解析与按钮状态 |
| 真实输入法体验 | 无须改变输入法选择，依次口述过滤、暂停原音、继续过滤、结束；暂停时本人及旁人声均可送入输入法，结束后不再接收该链路 |
| 切换响应与音频 | 建议暂停确认 ≤500 ms，进入原音最大输出间断 ≤100 ms；恢复过滤受已有预填充影响，报告实际最大断点，目标 ≤500 ms。无明显爆音、历史句子重放；超出门槛则先修复或明确调整门槛依据 |
| 稳定性与资源 | 30 分钟混合运行，包含多次 pause/resume；有界队列、无回调异常、无持续内存增长；过滤仍满足项目已有运行门槛，不能以原音模式掩盖不达标的过滤运行 |

实施时的检查入口：`uv run pytest`；Swift `Models.swift` 与 `Checks/ModelCheck.swift` 模型检查；`swift build --package-path app/MicForYouMenuBar`；再沿用既有真实麦克风、虚拟输入和豆包验收流程。具体新测试用例随上述契约实现；本轮未运行软件回归或真机收音。

## 发布与回退

- 保持 `Experimental Alpha` 与现有部分过滤、目标缺席时可能放行他人声的说明。
- 升级时不自动开始收音，不把旧版暂停记录迁移为正在直通；用户首次开始后进入新的控制路径。
- 运行状态 schema 提供明确版本和兼容读取，发布前保留原有配置；无需重新注册声音或更改输入法输入设备（除非用户更换实体麦克风）。
- 出现回归时先结束当前进程、释放设备，再回退构建；不把新状态记录给旧版本强行读取，也不在原音输出期间热替换运行文件。
- 软件验收通过后，移除新版视频中「暂停直通待软件更新」标注，再将其用于正式推广。视频当前仅演示用户已确定的目标交互。
